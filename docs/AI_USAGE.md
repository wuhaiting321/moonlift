## 2. 人（使用者）做了什么决策

这些不是 AI 自行决定的，都有对话记录：

## 3. 「AI 产出不会被当成证据」是怎么做到的

三条机制，缺一不可：

1. **独立实现做裁判。** 解码器对拍 `wabt`；行为正确性对拍 Node 的 `WebAssembly` 跑**原始模块**得到的答案。两边不是同一个作者、同一套代码，所以「自己跟自己一致」不算通过。
2. **钉住而不是叙述。** `script/check.sh` 把关键数字写成断言（`nodes 1136`、`blocks emitted 400 of 400`、`522/522/0`、150 个间接调用用例、79 个函数定义含 4 个桩、48 个模块）。数值一变门禁就红，文档里的数字不可能悄悄过期。
3. **编译不是行为。** 门禁专门加了「生成包必须真跑起来并与原件逐值对齐」这一步。三个真实的语义 bug（条件 `return` 被写成无条件、入口值读未绑定变量、`br_table` 载荷读没写过的临时量）**都能通过编译和结构覆盖率检查**，只有跑起来才暴露；这正是 AI 生成代码最容易漏、也最需要独立裁判的一类错误。

## 4. 已知偏差，不粉饰

- `PLAN.md` §7 原计划「随机输入 + trap 双方比较 + 内存哈希 + 浮点 ≤1 ULP」，实际实现是「固定对角序列 + 四组锚定行 + trap/NaN 跳过单列 + 浮点精确位比较」。原因写在 `BOUNDARY.md` §4.19 和 `ACCEPTANCE.md` §3 M3。
- 生成包的**行为**测试只在 `wasm-gc` 实跑，三端一致性的证据是分析输出与编译（`ACCEPTANCE.md` §3 M4）。
- `native` 后端本机不可用，已记录原因与安装命令，不静默省略。
