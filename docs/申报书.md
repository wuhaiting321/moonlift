## 一、项目基本信息

| 项 | 内容 |
|---|---|
| 项目名称 | **moonlift — Wasm 字节码到可编译 MoonBit 源码的反编译器** |

## 二、生态缺口（为什么做这个）

MoonBit 的 `wasm-gc` / `js` 后端**贴不了 C FFI**，大量存量 C/Rust 生态无法直接迁移；反编译是把既有 `.wasm` 产物搬进三端可用源码的通道，而不是再写一个解析库。

截至 2026-11-20，在 mooncakes.io 全量 **3,882 个模块**、GitHub 代码/仓库检索、Gitee 与已报名项目等**可检索范围内，未发现直接重复实现**：

| 检索 | 结果 |
|---|---|
| mooncakes.io 全量模块名/描述/关键词含 `decompiler` / `wasm2mbt` / `wasm2c` | **0** |
| GitHub `moonbit+decompiler`（`total_count`） | **0** |
| 最接近的邻居 | 只有 wasm 解析器 / 发射器，**没有代码恢复** |

> 这是对「可检索表面」的陈述，**不声称 100% 没有人做过**；也刻意避开了已有大量参赛者拥挤的生态模块方向。

## 三、方案与关键技术

八层流水线：`字节读取 → 12 个段 → 172 条 MVP 指令 → 基本块/CFG → 类型化栈与表达式重建 → 结构化控制流 → MoonBit 代码生成 → 差分验证`。

1. **宽解析、窄生成**：`info` 能解析 `v128` / 多返回值 / `datacount` / name 段；代码生成对不支持的函数**逐个报码并生成 trap 桩**，而不是整模块拒绝或静默降级。
2. **走 wasm 自带的构造树做结构化**（不写 Relooper）：实测 20 KB 真实编译器产物 78/78 个完整函数可归约，因为 `br` 只能指向外层标签；跨层分支用一个 `Int brk` 逐层解绕。被否方案：无条件 Relooper（普通 `if` 也变状态机，不可读）、图调度兜底（本子集不可达，是死代码）。
3. **边值在前驱落盘**：分支携带的值在边上由前驱写入临时量，而不是在使用点凭空读取；修复了 `br_if` 条件丢失、入口值未绑定、`br_table` 载荷读未写临时量三个「能编译但算错」的 bug。
4. **语义按实测分流**：与 MoonBit 一致的算子直接输出；除法溢出、`min(0,-0)= -0`、NaN 传播、ties-to-even 等语义不一致的走 `runtime/runtime.mbt` 具名 helper；浮点常量按**位模式**输出，避免打印往返丢掉 NaN 载荷或零的符号。
5. **三方独立验证**：MoonBit 出调用计划 → Node 跑**原始 wasm** 出答案 → bash 把答案写成生成包里的 `inspect` 测试 → `moon test` 跑**生成代码**比对。两边不是同一套实现。

## 四、边界（明确拒绝，不静默降级）

- **输入子集**：wasm v1 容器；12 个段；`i32/i64/f32/f64`；MVP 全集 + 符号扩展指令；仅函数导入。
- **明确拒绝并报码**：GC/引用类型 `E101`、SIMD `E102`、原子/线程 `E103`、异常 `E104`、尾调用 `E105`、多内存 `E106`、非函数导入 `E107`、批量内存 `E109`、`call_indirect` `E111`、多值 `E112`；每个诊断带**绝对字节偏移**。
- **13 条语义偏差**逐条写明「偏差 / 原因 / 影响面 / 是否可接受」，见 `BOUNDARY.md` §3（如 `block` → 一次性 `while true`、`brk` 变量、生成名与下划线、浮点按位、`start` → `moonlift_init()`）；**20 条已知限制**见 §4（含 native 未验证、trap/NaN 跳过、扩展语料只验形状不验行为）。
- **MVP 契约 M3/M4 有两处有意收缩**，已在 `ACCEPTANCE.md` §3 逐条申报：trap 在 MoonBit 是 abort 不可捕获，故跳过单列而非算通过；生成包的行为测试只在 `wasm-gc` 实跑，三端一致性证据为分析输出与编译。

## 六、开源合规与 AI 可解释

- **合规**：Apache-2.0；`NOTICE` 标注格式/算法参考；41 个 `.wasm` 全部自制或由 MoonBit 编译器产出，逐文件记录来源、SHA-256 与许可证，无第三方二进制。
